# ADR-001 Policy engine

Status: decided (2026-09-12); amended 2026-09-18 (V1), 2026-09-19 (write-check pointcuts), 2026-09-22 (V5 — evaluable subset), 2026-09-24 (phase 2 is one immediate check; PRECOMMIT resolves every reference)
Decision: **No external engine.** Medplum-shaped `AccessPolicy` resources are compiled per membership into (a) HAPI `AuthorizationInterceptor` rules — `resourceType × interaction` only — and (b) a Big Book criteria set enforced in HAPI hooks: pre-query narrowing at `STORAGE_PRESEARCH_REGISTERED` (every search, REST or GraphQL-nested), post-query drop at `STORAGE_PREACCESS_RESOURCES` (every returned resource, including `_include`/`_revinclude` and GraphQL references), `hiddenFields` at `STORAGE_PRESHOW_RESOURCES`, `readonlyFields` restore and the phase-1 (existing-resource) criteria check at `STORAGE_PRESTORAGE_RESOURCE_*`, the phase-2 (new-state) criteria check at `STORAGE_PRECOMMIT_RESOURCE_*`, and subscription-side enforcement on the delivery hooks. Cerbos rejected (adds a container to `lite`); OPA rejected (embeddable, but a second interpreter for a fixed schema that cannot evaluate FHIR criteria or filter fields).
Context: see `docs/BIGBOOK.md` → Open decisions; requirements unblocked: BB-R-006, BB-R-003.5, BB-R-005.3, BB-R-014.3. V1 evidence: issue #9.

## Rationale
- The hard parts of BB-R-006 — search-string `criteria`, `hiddenFields`, `readonlyFields`, parameter substitution — require the resource in the JVM and FHIR search semantics; neither Cerbos nor OPA has them. HAPI does (`InMemoryResourceMatcher`, `FhirTerser`, FhirPath).
- What remains for an engine (type × interaction × admin) is a native HAPI rule list.
- "Policies are data" is preserved: the data is the `AccessPolicy` resource; the translator is schema-fixed code, never per-type `if` statements.
- `lite` stays at three containers.
- (V1) `SearchNarrowingInterceptor` narrows the primary query only, and `FhirQueryRuleTester` fails closed by 403ing the whole request — a criteria-scoped caller could not use `_include` or GraphQL lists at all. Enforcement therefore moves to per-resource drop at `PREACCESS`, which runs before `AuthorizationInterceptor`'s own `PRESHOW` check and is the pointcut HAPI built for dropping.

## Consequences
- **Enforcement path.** `PRESEARCH_REGISTERED` (narrow the `SearchParameterMap`: criteria; ORed policies via `_filter`, else post-only) → `AuthorizationInterceptor` (type × interaction; `allowAll` for super-admin; injected admin-type rules for `membership.admin`; cached per membership on policy versions) → `PREACCESS` (drop resources failing criteria — search entries, includes, GraphQL references, `$everything`, history, transaction responses) → `PRESHOW` (`hiddenFields`) → `PRESTORAGE_RESOURCE_UPDATED/DELETED` (phase 1: existing resource inside criteria → else 403; `readonlyFields` restored from prior version) → `PRECOMMIT_RESOURCE_CREATED/UPDATED` (phase 2: committed state inside criteria, references resolved → else 403 and rollback; whole bundle for `transaction`, single entry for `batch`) → `SUBSCRIPTION_RESOURCE_MATCHED` / `…BEFORE_REST_HOOK_DELIVERY` (author's policy applied to firing and payload).
- **Collection vs single-resource semantics.** Collections filter silently, never 403. Single `read`/`vread` outside criteria → 404 (HAPI's result for a `PREACCESS` drop; reconcile with `medplum-parity.md`). Writes outside criteria → 403.
- **Paging rule.** Every search is narrowed pre-query, so `_count`, `_total` and `next` are exact; a `PREACCESS` drop on a primary-query entry is a narrowing defect and logs WARN. `_include`/`_revinclude` are outside `_count` and never refilled. GraphQL nested lists are searches and are narrowed at `PRESEARCH_REGISTERED`; if that pointcut fails verification for nested searches, lists may be short and connection `count` is the DB count — record in `medplum-parity.md`.
- **Removed from the design:** `FhirQueryRuleTester`, `SearchNarrowingInterceptor`/`AuthorizedList`. Partition scoping stays with `STORAGE_PARTITION_IDENTIFY_*`.
- **Criteria are validated at write time** against the in-memory matcher's supported subset (`:not`, **no `:missing`**, no chaining — enforced, not conventional); unparseable criteria fail closed (D14, D15). *Amended 2026-09-22, measured on 8.12.1: `:not` evaluable, `:missing` not; `:missing` rejected at write time.*
- **The evaluable subset is narrower than what HAPI reports supported** (2026-09-22, V5). Two forms report supported and **fail open**, so Big Book refuses them at write time even though HAPI and Medplum accept them: an **empty parameter value** (`Observation?status=`) matches *every* resource of the type, and **`:in`/`:not-in`** compare against an unexpanded ValueSet, so `:in` matches nothing and `:not-in` matches everything. Anything that reaches the compiler anyway compiles to `Criteria.Never`. Recorded as a deliberate divergence in `medplum-parity.md`.
- **Write-check pointcuts.** Phase 1 (old state) and `readonlyFields` at `PRESTORAGE_*`, which is HAPI's modify hook and needs no reference resolution. Phase 2 (new state) at `PRECOMMIT_*`, a single immediate check. Inside a `transaction`, `PRECOMMIT` sees **every** reference already substituted — conditional, `urn:uuid`, and forward references alike (measured on 8.12.1 by serialising at the pointcut, #35) — because HAPI pre-assigns placeholder ids before processing entries. One code path for single writes and bundle entries. Over-refusal is not acceptable here: refusing an unresolved reference would 403 the canonical Patient + Observation bundle for every criteria-scoped caller, which is BB-R-001's headline exit shape. v0.2 `writeConstraint`: `%before` at `PRESTORAGE`, `%after` at `PRECOMMIT`.
- **Storage:** `AccessPolicy` served at `/fhir/R4/AccessPolicy` in Medplum JSON from a Big Book Postgres table partitioned by `project_id`, via a plain `IResourceProvider` — same pattern as the other Medplum admin types (ADR-003, v0.2). Not HAPI JPA unless custom `@ResourceDef` types are verified clean on the pinned version.
- **Policy semantics per inventory T1–T3:** only `Project.superAdmin` bypasses; `membership.admin` = own policy + injected admin-type rules; `ProjectMembership.access[]{policy, parameter[]}` concatenates and ORs; built-in parameters are `%profile` and `%patient`; a membership with no policy compiles to full project access.
- **Glue budget ≈ 1.4–1.6k lines:** translator ~400, `PRESEARCH` narrowing ~120, `PREACCESS` drop ~150, `hiddenFields` ~150, `readonlyFields` ~100, post-write check ~50, write-time validation ~60, params ~100, interaction split ~60, subscriptions ~100, denial log ~50, backstop WARN ~20, verification-dependent extras ≤200. Defaults/promote-demote (~150) charged to BB-R-005.
- Deferred v0.2 items unaffected or easier: `writeConstraint` (~100, in-JVM FhirPath), binary security context (same `PREACCESS` path), SMART scopes (scopes → `AccessPolicy.resource[]`, translator unchanged). IP rules are not a policy-engine concern.
- **Exit test additions (BB-R-006):** criteria-scoped caller runs `GET /Observation?_include=Observation:subject` where the Patient is outside criteria → 200, include entry absent; `$graphql` `ObservationList` → only visible entries, no 403; primary-query page length = `_count` with `_total=accurate` matching.

## Reversal cost
**If a future HAPI stops substituting placeholders before `PRECOMMIT`,** phase 2 needs a deferred re-check, and the mechanism is already
verified rather than hypothetical (measured on 8.12.1, `DeferredPhase2VerifyTest`, #35): a Spring
`TransactionSynchronization` registered from a `PRECOMMIT` hook runs `beforeCommit` **inside** HAPI's transaction and throwing there rolls
back every entry (a); a re-read in `beforeCommit` returns substituted references, **provided it carries the caller's partition** — a bare
`SystemRequestDetails` is refused with `HAPI-1319` (b); `batch` entries transact per entry, so the path degrades to per-entry there (c).
Cost ≈60 lines: a deferral queue in `RequestDetails`, the synchronization, and the re-read. It is deliberately **not built** — dead code on
8.12.1 and on every version in the roadmap (ruled 2026-09-24) — but the trigger is narrow and the evidence is in the repo, so reversing this
is a day's work rather than a re-investigation.

Low. The `AccessPolicy` JSON contract and the compile step are the seam: retargeting the ~400-line translator core from HAPI rules to an OPA/Cerbos decision call is the whole change. Criteria drop, `hiddenFields`, `readonlyFields`, `writeConstraint` and subscription enforcement stay in HAPI hooks under any engine. Trigger for reversal: a real need for open-ended ABAC beyond the AccessPolicy schema.

## Amendments
- 2026-09-21 — #33: phase 2 was split into immediate and deferred (`TransactionSynchronization.beforeCommit`) paths on the understanding that `PRECOMMIT` does not resolve `urn:uuid` placeholders inside a `transaction`. **Corrected 2026-09-24 (#35): it does.** Measured on 8.12.1 by *serialising the resource at the pointcut* rather than reading a live getter, so it is not a later-mutation artifact: conditional references, `urn:uuid` placeholders and even a **forward reference** (Observation entry 1 → Patient entry 2) all arrive substituted, because HAPI pre-assigns placeholder ids before processing entries.
